Olaryn BillingBilling, credits and usage

Before a job starts, Olaryn Billing puts the cost on hold. When it’s done, people pay only for what was used. The rest goes back.

What happens behind the scenes
  1. Hold the costThe product works out the price and Olaryn Billing sets those credits aside.
  2. Do the workThe held credits can’t be spent on anything else in the meantime.
  3. Charge what was usedUnused credits go straight back. If the job is cancelled, all of them do.

Accounting safeguardsfor credits and billing

The accounting rules used when processing reservations, payments and refunds.

  • No double spendingTwo jobs that each need 25 credits, with only 35 left: exactly one goes ahead.
  • Pay first, then accessPlans and allowances change only after a payment has really gone through.
  • Safe to try againIf a request is sent twice, it still only counts once.
  • Refunds take credits backWhen a payment is refunded or disputed, the credits it bought are removed.

For developershold, then charge or cancel

A product requests a credit hold, settles actual usage or releases the reservation. Requests carry an Olaryn Identity token.

Example requests

# 1. Hold the cost before the work starts
POST /v1/{product}/customers/{customer}/reservations
Authorization: Bearer <Olaryn Identity machine token>
{
  "amount": 12,
  "operation": "export-report",
  "idempotency_key": "<same key if you retry>",
  "resource_type": "report",
  "resource_id": "<report id>"
}

# 2a. Work finished: charge what was used
POST .../reservations/{id}/settle
{ "amount": 9 }

# 2b. Work cancelled: give the credits back
POST .../reservations/{id}/release
{ "reason": "cancelled" }
